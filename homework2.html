Homework 2: From Wallet Seed to Ethereum Address

Analysis of the practical cryptographic pipeline, standards, and historical evolution in Ethereum wallets

1. The Practical Ethereum Wallet Pipeline

An Ethereum wallet does not rely on a single algorithm; it relies on a sequence of standards and cryptographic primitives that, when combined, form the cryptographic pipeline that will transform a user-friendly seed phrase into an Ethereum addess. The exact procedure is the following:

Mnemonic (BIP-39) ↓ PBKDF2 with HMAC-SHA512 Master Seed ↓ HD Key Derivation (BIP-32 / BIP-44) ↓ Private Key ↓ (secp256k1 Elliptic Curve) Public Key ↓ (Keccak-256 Hashing - last 20 bytes) Raw Ethereum Address ↓ (EIP-55 Checksum Encoding) Checksummed Address (Mixed-Case)

2. A deep dive into the Ethereum wallet's Standards and Cryptographic Primitives

  • BIP-39 (Mnemonic Sentence & Seed): It trasforms entropy (128 to 256 bits of high-quality randomness) into a human-friendly sentence of 12 to 24 words chosen from a standardized list. It then applies PBKDF2 (a Key Derivation Function) using HMAC-SHA512 to stretch the mnemonic into a deterministic 512-bit binary seed.
  • BIP-32 (Hierarchical Deterministic Key Derivation): It introduces an HD structure where a single master seed can deterministically generate an infinite tree of parent and child key pairs. This eliminates the need to continuously backup new individual private keys.
  • BIP-44 (Multi-Account Path Standard): It etablishes a logical hierarchy for deterministic paths (e.g., m / purpose / coin_type / account / change / address_index), enabling multi-currency and multi-account support.
  • secp256k1 (Elliptic-Curve Cryptography): It's the specific Koblitz curve used by Ethereum and Bitcoin ($y^2 = x^3 + 7 \pmod p$) to derive public keys from private keys and handle digital signatures via ECDSA.
  • Keccak-256 (Hashing Function): It compresses the public key into a fixed-size output. The rightmost 20 bytes of this hash form the base Ethereum address.
  • EIP-55 (Mixed-Case Checksum): It's a smart encoding convention that capitalizes specific letters in the address hash to provide built-in error detection against typing mistakes.

3. Core Conceptual Distinctions

To analyze wallet security accurately, there are some concepts that need special attention:

Key Generation
The process of creating a new, independent cryptographic key from scratch using a Cryptographically Secure Pseudo-Random Number Generator (CSPRNG). If you run key generation twice, the keys you will obtain will be completely unrelated. Because of this reason, if you generate multiple random keys you also must back up every one of them.
Key Derivation
The process of mathematically calculating new keys from an existing master secret (a seed or parent key) using a deterministic one-way function. It works by passing the parent secret and a specific index or path through cryptographic algoritgms or elliptic curve math. Since the keys are derived rather than randomly generated, there's no need to back up every one of them.
Public-Key Cryptography
A cryptographic system that uses a pair of mathematically linked keys for encryption, decryption and digital signatures. The main feature of this cryptographic system is the fact that the key is shared openly with anyone. It is used to encrypt messages intended for the owner (who will later decrypt it with the private key) or to verify digital signatures created by the owner's private key.
Hashing
A mathematical operation performed by a cryptographic hash function that takes an input of any arbitrary size and converts it into a fixed-size string of bits (called hash, digest or output). In blockchain systems like Ethereum, cryptographic hash functions have the properties of being deterministic (the exact same input will always produce the exact same digest), one-way (it is computationally easy to compute the hash from the input but practically impossible to reverse the process to find the original input), Collision Resistant (it is extremely difficult to find two completely different inputs that produce the exact same digest) and Avalanche Effect (changing even a single bit in the input radically alters the output).
Checksums
Error-detecting codes added to data to ensure that information has not been corrupted, altered or mistyped during transmission or storage. They are generated through a mathematical algorithm (a hashing or checksum function) that procudes a short string of characters or digits.
Encoding
The process of converting data from one format, system or alphabet into another, using a publicly known, standarized and fully reversible set of rules. Its purpose is to make data compatible with a specific medium, system or human reader. Since the algorithm or the set of rules are public anyone can easily decode the data back to its original form, therefore it does not provide encryption, secrecy or security.

4. Temporal and Historical Context

  • 1977 — RSA: Introduction of public-key cryptography, laying the mathematical groundwork for asymmetric encryption.
  • 2001 — SHA-2 / SHA-512: Standardization of secure hash algorithms by NIST.
  • 2012 — BIP-32: Invention of Hierarchical Deterministic wallet structures.
  • 2013 — BIP-39: Introduction of mnemonic sentences for user-friendly wallet backups.
  • 2014 — BIP-44: Multi-account path standards for deterministic wallets.
  • 2015 — SHA-3 / Keccak: NIST standardizes SHA-3 based on the Keccak submission. Note: Ethereum's Keccak-256 differs slightly from the final NIST SHA3-256 standard due to pre-NIST parameter and padding choices.
  • 2016 — EIP-55: Introduction of mixed-case checksum addresses to prevent user fund losses on Ethereum.

5. Architectural Modularity: Why Multiple Algorithms?

An Ethereum wallet delegates responsibilities to specialized layers rather than using a single monolithic algorithm:

  • BIP-39 / BIP-32 / BIP-44 handle human usability and key management.
  • secp256k1 handles ownership verification, authentication, and digital signatures.
  • Keccak-256 handles deterministic data compression and address reduction.
  • EIP-55 handles human-error protection and integrity checks.

Combining these specialized components ensures maximum security, cryptographic separation of concerns, and resilience against single points of failure.
