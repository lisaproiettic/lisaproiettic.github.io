Homework 2: From Wallet Seed to Ethereum Address

Analysis of the practical cryptographic pipeline, standards, and historical evolution in Ethereum wallets

1. The Practical Ethereum Wallet Pipeline

An Ethereum wallet does not rely on a single algorithm; it relies on a sequence of standards and mathematical functions that, when combined, form the cryptographic pipline that will transform a user-friendly seed phrase into an Ethereum addess. The exact procedure is the following:

Mnemonic (BIP-39) ↓ Master Seed ↓ HD Key Derivation (BIP-32 / BIP-44) ↓ Private Key ↓ (secp256k1 Elliptic Curve) Public Key ↓ (Keccak-256 Hashing - last 20 bytes) Raw Ethereum Address ↓ (EIP-55 Checksum Encoding) Checksummed Address (Mixed-Case)

2. Role of Standards and Cryptographic Primitives

  • BIP-39 (Mnemonic Sentence & Seed): Converts a 12-to-24 word human-readable sequence into a cryptographic master seed using key stretching (PBKDF2). This allows users to easily back up their wallet on paper.
  • BIP-32 (Hierarchical Deterministic Wallets): Introduces an HD structure where a single master seed can deterministically generate an infinite tree of parent and child key pairs.
  • BIP-44 (Multi-Account Path Standard): Establishes a logical hierarchy for deterministic paths (e.g., m / purpose / coin_type / account / change / address_index), enabling multi-currency and multi-account support.
  • secp256k1 (Elliptic-Curve Cryptography): The specific Koblitz curve used by Ethereum and Bitcoin ($y^2 = x^3 + 7 \pmod p$) to derive public keys from private keys and handle digital signatures via ECDSA.
  • Keccak-256 (Hashing Function): Compresses the public key into a fixed-size output. The rightmost 20 bytes of this hash form the base Ethereum address.
  • EIP-55 (Mixed-Case Checksum): A smart encoding convention that capitalizes specific letters in the address hash to provide built-in error detection against typing mistakes.

3. Core Conceptual Distinctions

To analyze wallet security accurately, we must distinguish between several fundamental operations:

  • Key Generation vs. Key Derivation: Generation creates initial randomness (e.g., generating a private key or seed), whereas derivation uses a deterministic algorithm (like BIP-32) to compute child keys from a parent seed without additional randomness.
  • Public-Key Cryptography: Asymmetric mathematics (secp256k1) ensuring that a private key can sign data and generate a public key, while making the reverse computation computationally infeasible.
  • Hashing: One-way data compression (Keccak-256) mapping inputs of arbitrary size to fixed-size outputs, stripping away algebraic structures.
  • Checksums: Error-detection mechanisms (EIP-55) embedded into data representations to flag typos.
  • Encoding: Formatting raw binary data into human-readable representations (such as hex strings or BIP-39 English words).

4. Temporal and Historical Context

These technologies evolved progressively over decades to solve emerging challenges in distributed systems:

  • 1977 — RSA: Introduction of public-key cryptography, laying the mathematical groundwork for asymmetric encryption.
  • 2001 — SHA-2 / SHA-512: Standardization of secure hash algorithms by NIST.
  • 2012 — BIP-32: Invention of Hierarchical Deterministic wallet structures.
  • 2013 — BIP-39: Introduction of mnemonic sentences for user-friendly wallet backups.
  • 2014 — BIP-44: Multi-account path standards for deterministic wallets.
  • 2015 — SHA-3 / Keccak: NIST standardizes SHA-3 based on the Keccak submission. Note: Ethereum's Keccak-256 differs slightly from the final NIST SHA3-256 standard due to pre-NIST parameter and padding choices.
  • 2016 — EIP-55: Introduction of mixed-case checksum addresses to prevent user fund losses on Ethereum.

5. Architectural Modularity: Why Multiple Algorithms?

An Ethereum wallet delegates responsibilities to specialized layers rather than using a single monolithic algorithm:

  • BIP-39 / BIP-32 / BIP-44 handle human usability and key management.
  • secp256k1 handles ownership verification, authentication, and digital signatures.
  • Keccak-256 handles deterministic data compression and address reduction.
  • EIP-55 handles human-error protection and integrity checks.

Combining these specialized components ensures maximum security, cryptographic separation of concerns, and resilience against single points of failure.
