1. Toy ECC Encryption on secp256k1 (ElGamal / ECIES style)

This part uses the real secp256k1 parameters (y² = x³ + 7 over a 256-bit prime field), but the private key k is drawn from a small range [1, 2b]. The curve (and so G) is the real one, so the scheme works exactly as in Ethereum, while the restricted key makes the attack in Section 5 computationally feasible. (The mod-17 curve of Homework 1 has only 18 points, which is too small to give a meaningful key space.)

Algorithm and role of the keys

  • Private key k (secret, kept by the receiver) and public key Q = kG (published). Recovering k from Q is the ECDLP.
  • Encryption (needs only Q): pick a random ephemeral r; compute C₁ = rG and the shared secret S = rQ; derive a keystream from SHA-256(x(S) || counter); XOR it with the message. Output (C₁, ciphertext).
  • Decryption (needs k): compute S = kC₁ = k(rG) = r(kG) = rQ, derive the same keystream and XOR again.
Press "Generate keys" to start.

2. The Caesar Cipher

Each letter is shifted by the key s ∈ {0,…,25}: E(x) = (x + s) mod 26, D(y) = (y − s) mod 26. Case, spaces and punctuation are preserved.

4. Statistical Cryptanalysis of the Caesar Cipher

            
Idea. Caesar is a monoalphabetic substitution, so the letter histogram of the ciphertext is the histogram of the language, rotated by s. For every candidate shift s' we decrypt and score how well the result matches reference statistics learned from a training corpus; the best score wins. Three scorers are compared:

            
    
                
  • χ² on letter frequencies: Σ (Oi − Ei)² / Ei, lowest wins.
    • 
                
  • Bigram log-likelihood (n-gram scoring, n = 2): Σ log P(ab) over adjacent letters, highest wins.
    • 
                
  • Exhaustive search + dictionary: try all 26 shifts and count common English words in the output.

Discussion

            
    
                
  • Effectiveness: with a few hundred letters every method is essentially always right, because the letter histogram converges to the language distribution (law of large numbers).
    • 
                
  • Limitations: on very short ciphertexts the observed histogram is a small, noisy sample, and different shifts can score similarly (ambiguity is also possible: a very short text can be a valid word under several shifts). Success rates drop sharply below about 20 letters.
    • 
                
  • Method comparison: the unigram χ² uses only 26 numbers; bigrams add context and typically win on short texts; the dictionary test needs word boundaries and fails on texts with few common words. All of them rely on the corpus matching the language and style of the plaintext.

5. Attack on the Toy ECC Scheme

            
The attacker knows Q, C₁ and the ciphertext, and knows that k ∈ [1, 2b]. Once k is found, S = kC₁ and the message is decrypted as in Section 1. Use the keys and ciphertext generated in Section 1 (press the three buttons there first).

            
    
                
  • Brute force: compute G, 2G, 3G, … until iG = Q. Cost O(N) point additions, with N = 2b.
    • 
                
  • Baby-step giant-step (BSGS): with m = ⌈√N⌉, store the baby steps jG (0 ≤ j < m) in a hash table, then walk Q − i·mG until it hits the table. Then k = i·m + j. Cost O(√N) time and memory.
    • 
            

 
            
            
            
Generate keys and encrypt in Section 1 first.

 
            
Discussion

            
    
                
  • Difference from the Caesar attack: the Caesar attack is statistical: it works because the ciphertext leaks the plaintext distribution, and it can be wrong on short texts. The ECC attack uses no statistics on the ciphertext (which looks random): it is a search over the key space with an exact test (kG = Q), so when it terminates the answer is certainly correct. Its cost depends only on the key-space size, not on the message length.
    • 
                
  • Why it does not scale: for a proper 256-bit private key, brute force needs about 2256 additions and BSGS about 2128 operations and 2128 memory; Pollard's rho needs about 2128 time with negligible memory. Both are far beyond any feasible computation. Each extra key bit doubles the brute-force cost and multiplies the generic attack cost by √2.
    • 
                
  • Weaknesses from the restricted key space: a small k makes O(√N) generic attacks (BSGS, rho, kangaroo for a known interval) trivial. The curve itself is not weakened, only the search space.
    • 
                
  • Weaknesses from the design of the toy scheme: (i) no authentication, so the ciphertext is malleable (flipping a ciphertext bit flips the same plaintext bit); (ii) reusing r reuses the keystream, so C ⊕ C' = M ⊕ M'; (iii) C₁ is not checked to be on the curve, which allows invalid-curve attacks; (iv) the SHA-256 counter mode is an ad-hoc KDF, not a standard one such as HKDF; (v) the message length is not hidden.
