Homework 3: Cryptanalysis & Comparative Security

Comparative analysis of classical ciphers vs. toy elliptic curve cryptography, statistical cryptanalysis, and key-space vulnerability assessments.

1. Encryption & Decryption: Toy ECC vs. Caesar Cipher

To establish a direct baseline between classical and modern primitives, we process a simple alphanumeric message using both a Caesar Cipher (classical substitution) and a Toy Elliptic Curve Scheme based on $y^2 = x^3 + 7 \pmod{17}$ (modern public-key structural mapping).

Target Message: HELLO (Mapped to numerical indexes or character streams)

Procedure & Algorithmic Roles

  • Caesar Cipher (Shift $k = 3$): Each plaintext letter is shifted forward alphabetically by 3 positions (e.g., H $\to$ K). Decryption reverses the operation by shifting backward by $k$. The key space is extremely restricted ($K \in [0, 25]$).
  • Toy ECC Scheme ($Q = kG$): Messages or keys are mapped to curve points. Using base point $G=(1,5)$ and private key $k=6$, the public point is derived as $Q = 6G = (5,8)$. Encryption/decryption relies on scalar point multiplication over a finite field $\mathbb{Z}_{17}$.

Comparative Analysis

Feature Caesar Cipher Toy secp256k1 ECC Scheme
Mathematical Basis Modular arithmetic shift ($\pmod{26}$) Group law on elliptic curves over finite fields ($\pmod{17}$)
Key Space 26 possible keys (trivial search space) Restricted range in toy model ($[1, 18]$); $2^{256}$ in production
Statistical Property Preserves plaintext letter frequencies (monogram structure intact) Produces structural point outputs; destroys linguistic correlations
Directionality Symmetric (same key for encrypt/decrypt) Asymmetric structure (Private key $k$, Public point $Q$)

2. Statistical Cryptanalysis of the Caesar Cipher

Because the Caesar cipher performs a simple monoalphabetic substitution, it preserves the intrinsic statistical properties of the underlying language. By analyzing character frequencies (monograms, e.g., 'E' or 'A' in English/Italian), an attacker can reliably recover the hidden key.

Frequency Analysis Algorithm

The cryptanalysis process follows these core steps:

  1. Compute the frequency distribution of letters in the given ciphertext.
  2. Compare the resulting histogram against the known language standard distribution vector.
  3. Identify the peak shift (distance) between the most frequent ciphertext letter and the language's expected most common letter (e.g., 'E').
  4. Exhaustively test candidate shifts or score alternatives using chi-squared statistics or n-gram scoring.

Impact of Text Length & Limitations

Effectiveness vs. Text Size:
  • Short Ciphertexts: Statistical anomalies heavily distort frequency distributions. A 10-character ciphertext may lack standard 'E' or 'T' frequencies entirely, causing frequency analysis to fail or produce false positives.
  • Long Ciphertexts: Large text bodies closely approximate theoretical language distributions, allowing the automated attack to recover the key with near 100% accuracy almost instantaneously.

3. Restricted Key Space Attack vs. Statistical Attack

In our toy implementation, the secp256k1 curve uses modulus $p = 17$ with a very small group order ($N = 18$), drastically restricting the private key space to make manual or script-based verification feasible.

Executing the Brute-Force Attack

Given the public output or ciphertext mapping, an attacker can trivially perform a brute-force search across all possible private keys $k \in [1, 18]$:

// Pseudo-code for Toy ECC Key Recovery
let target_point = {x: 5, y: 8}; // Q = 6G
let current_point = null;
let G = {x: 1, y: 5};

for (let k = 1; k < 18; k++) {
    current_point = pointAdd(current_point, G);
    if (current_point.x === target_point.x && current_point.y === target_point.y) {
        console.log(`Private key recovered: k = ${k}`);
        break;
    }
}

Key Differences: ECC Brute-Force vs. Caesar Statistical Attack

  • Attack Vector: The Caesar attack exploits language redundancies and statistical predictability. The Toy ECC attack exploits an artificially constrained hardware/mathematical boundary (small key space).
  • Feasibility on Real Systems: While a Caesar cipher remains insecure regardless of implementation details (due to small keyspace + frequency leakage), a properly configured real-world ECC scheme using secp256k1 operates over a key space of roughly $\approx 1.15 \times 10^{77}$ ($2^{256}$). A brute-force search over this space is computationally impossible with current or foreseeable physics.

4. Conclusion & Security Takeaways

The progression from classical ciphers (Caesar) to modern asymmetric structures (ECC) highlights the evolution of defensive cryptography:

  • Classical systems fail because they maintain data patterns (statistical leakage).
  • Toy models demonstrate mathematical principles clearly but fail in security due to narrow parameter scales.
  • Real-world modern cryptography combines algebraic hardness (ECDLP) with massive entropy spaces to eliminate both statistical and brute-force vulnerabilities.
